# v1 待选端点清单

基于 core 现有能力与协议已有 7 个端点（employees / runtime / assemble / turn / events / sessions / sessions/:id）的差集，筛除 admin、Slack、浏览器专属端点后，甲方场景下有意义的候选。按分组勾选后一次性实现（网关路由 + 测试 + protocol.md + demo 接入）。

## A. 消息运行时（跟 turn/events 直接相关，价值最高）

| #   | 候选端点                                      | 中文解释                                                                       | 备注                                       |
| --- | --------------------------------------------- | ------------------------------------------------------------------------------ | ------------------------------------------ |
| 1   | `POST /v1/runs/:id/signal`                    | 给运行中的 run 发信号：追加消息（如「补充一下信息」）、中断、回答 agent 的提问 | 交互式体验的关键，配合 events 用           |
| 2   | `POST /v1/runs/:id/withdraw`                  | 撤回排队中/运行中的 run                                                        | 甲方可取消误发的消息                       |
| 3   | `GET /v1/sessions/:id/approvals`              | 列出待审批的敏感操作（如 agent 想执行命令等待确认）                            | 与 turn 的 `approval` 字段配对，是闭环必需 |
| 4   | `GET /v1/sessions/:id/background`             | 查看沙箱后台任务（agent 在沙箱里跑的长任务）                                   | 只读，风险低                               |
| 5   | `GET /v1/sessions/:id/background/:pid/output` | 查看沙箱后台任务的输出                                                         | 只读，风险低                               |
| 6   | `GET /v1/sessions/search?q=`                  | 跨会话全文搜索                                                                 | 甲方做客服记录检索有用                     |

## B. 会话管理

| #   | 候选端点                            | 中文解释                      | 备注                           |
| --- | ----------------------------------- | ----------------------------- | ------------------------------ |
| 7   | `PATCH /v1/sessions/:id`            | 改会话标题 / 归档             | 补齐甲方侧会话管理 UI          |
| 8   | `POST /v1/sessions/:id/fork`        | 从某条消息分叉出新会话        | 试错场景（「换个问法重新来」） |
| 9   | `GET /v1/sessions/:id/entries/:seq` | 读取会话历史中单条 entry      | 现有 tailTurns 不够深时翻页用  |
| 10  | `GET /v1/conversations` / `/:id`    | 按 threadRef 查会话容器元信息 | 与 sessions 略重叠，优先级低   |

## C. 文件（注意：有二进制上传的坑）

| #   | 候选端点                                   | 中文解释                            | 备注                                                                                |
| --- | ------------------------------------------ | ----------------------------------- | ----------------------------------------------------------------------------------- |
| 11  | `GET /v1/files?scopeId=`                   | 列出员工沙箱产生的文件              | 只读，安全；**前端文件工作区的列表源**（`direction:"out"` 即 AI 生成）              |
| 12  | `GET /v1/files/:id/content`                | 下载文件内容（如 agent 生成的报表） | 只读，安全；**文件工作区的查看源**；demo 场景价值高                                 |
| 13  | `POST /v1/files/upload` / `POST /v1/blobs` | 上传文件给 agent                    | ⚠️ 二进制 body 与现有 HMAC 签名（UTF-8 读体）冲突，需改签名方案或独立通道，成本最高 |

## D. 记忆

| #   | 候选端点                  | 中文解释               | 备注                                                         |
| --- | ------------------------- | ---------------------- | ------------------------------------------------------------ |
| 14  | `GET /v1/memory?scopeId=` | 读取员工的长期记忆条目 | 甲方展示「员工记住了什么」                                   |
| 15  | `POST /v1/memory` / 删除  | 增删记忆               | ⚠️ 让甲方改 agent 的记忆，可能破坏人格一致性，建议慎开或只读 |

## E. 其他

| #   | 候选端点                                                      | 中文解释                                                                     | 备注                                                                             |
| --- | ------------------------------------------------------------- | ---------------------------------------------------------------------------- | -------------------------------------------------------------------------------- |
| 16  | `PUT /v1/soul` + `PUT /v1/standing-orders`（独立改人格/形象） | 重写员工人格/形象（现在 soul/standingOrders 只能建员工时写入，只能重建员工） | 痛点真实，core 已有 `POST /v1/soul` 和 `PUT /v1/contexts/policy`，只需网关包一层 |
| 17  | `GET /v1/crons` 系                                            | 定时任务（查看/建员工定时报表等）                                            | 场景好但涉及排队与审批语义，工作量中等                                           |
| 18  | `GET /v1/keychain/overview`                                   | 查看员工已连接的凭据                                                         | ⚠️ 涉及凭据面，demo 阶段不建议                                                   |

## 推荐勾选

优先 **1-6（A 组全部）+ 16（独立改人格/形象）**——它们补齐「对话闭环」最后缺口（交互、取消、审批、改人格不用重建员工），全部是 JSON 小载荷、无二进制、风险可控。

**11+12（文件列表+内容查看）** 是前端文件工作区的完整后端需求（`direction:"out"` 即 AI 生成的文档），建议提为必做。

13（上传）等真有需求再设计签名方案；14（记忆）只做只读，15 慎开；B 组按 UI 需要挑选（7/8/9 常用，10 优先级低）；17/18 靠后。
